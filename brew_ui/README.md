# brew_ui

The shared design *system* for Brew apps: tokens, a theme builder, and
unopinionated primitives. Not a shared *look*. Each app passes its own palette,
font and radii, so BREW, BrewWire and WealthBrew read as one family without
looking borrowed from each other.

No Brew dependencies. Widgets take callbacks; the app wires them to
`brew_auth` and `brew_core`.

## Theming an app

```dart
const seed = Color(0xFF1E88E5);

MaterialApp(
  theme: buildBrewTheme(colors: BrewColors.fromSeed(seed)),
  darkTheme: buildBrewTheme(
    colors: BrewColors.fromSeed(seed, brightness: Brightness.dark),
  ),
  themeMode: ref.watch(brewThemeModeProvider).value ?? ThemeMode.system,
)
```

A hand-tuned palette uses the `BrewColors(...)` constructor instead of
`fromSeed`. Pass `fontFamily`, `shape: BrewShape(control: 8, card: 10)` and the
app's own ThemeExtensions (`extensions: [...]`) to keep its identity.

Widgets read tokens with `context.brewColors`, `context.brewType` and
`context.brewShape`. Those fall back to the ambient Material theme, so brew_ui
widgets work in an app whose theme hasn't been migrated yet.

## What's here

| | |
|---|---|
| **Tokens** | `BrewColors` (surface tiers, accent/secondary, 3 text levels, status + readable `…Text` shades, `BrewTone`), `BrewTypography`, `BrewShape`, `BrewSpacing`, `BrewBreakpoints`, `BrewMotion` (with reduced-motion checks) |
| **Theme** | `buildBrewTheme`, `ThemeModeStore` + `brewThemeModeProvider` |
| **Primitives** | `BrewButton`, `BrewCard`, `BrewPressable`, `BrewTextField`, `BrewApiKeyField`, `BrewSectionHeader`, `BrewStatusPill`, `BrewShimmer`, `BrewEmptyState`, `BrewErrorState` + `classifyError`, `showBrewConfirmDialog`, `showBrewTextInputDialog`, `BrewContentWidth` |
| **Auth parts** | `BrewAuthCard`, `BrewSignInButton`, `BrewEmailPasswordForm`, `BrewDividerLabel`, `BrewBackendSetupForm` (first run of a prebuilt release) |
| **Settings parts** | `BrewSettingsSection`, `BrewSettingsTile`, `BrewThemeModeTile`, `BrewAccountSection`, `BrewCredentialTile` (the collapsed-card key form brew_core's README describes) |
| **Shell** | `BrewAdaptiveShell`: bottom bar → rail → extended rail by width |
| **Gallery** | `BrewComponentGallery`: everything on one page, for a debug route |

A login screen, for example, is the app's own composition:

```dart
BrewAuthCard(
  title: 'BrewWire',
  subtitle: 'Your news, summarised',
  logo: const AppLogo(),
  children: [
    BrewSignInButton(
      kind: BrewSignInKind.google,
      onPressed: () => auth.signInWithOAuth(OAuthProvider.google),
    ),
    const BrewDividerLabel('or'),
    BrewEmailPasswordForm(onSubmit: (email, password, signUp) async {
      if (!signUp) return auth.signInWithEmail(email, password).then((_) => null);
      final res = await auth.signUpWithEmail(email, password);
      return res.session == null ? 'Check your inbox to confirm.' : null;
    }),
  ],
)
```

## Tests

- **Behaviour:** every primitive, the forms' validation, the dialogs, the
  shell's breakpoints.
- **Accessibility:** the whole gallery, light and dark, for four app-like
  seeds, against Flutter's tap-target, labelled-target and text-contrast
  guidelines. A deliberately unreadable palette has to fail the contrast check,
  so a pass means something.
- **Goldens:** the gallery, light and dark. Linux only (fonts rasterise
  differently per OS), generated by the manual **Regenerate golden baselines**
  workflow. Download its artifact, look at it, and commit it to
  `test/goldens/baselines/`. Never regenerate on macOS.
